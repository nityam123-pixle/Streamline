## Minor

### 🟡 Clipboard feedback triggers on failure, `src/components/team-invitation/ShareLinkCard.tsx:42`
**Problem**: In `handleCopy`, `setCopied(true)` is executed unconditionally outside the `if (success)` check. If both `navigator.clipboard.writeText` and the fallback `document.execCommand("copy")` throw an error, the button still displays "Copied invite link".  
**Why it matters**: Users in restricted permissions environments or non-secure contexts could see a false positive confirmation that the link was copied when clipboard writing actually failed.  
**Suggested fix**: Wrap `setCopied(true)` in `if (success)` and log or surface a notification if both attempts fail.

### 🟡 Missing x-forwarded-host in shareable invite link construction, `src/actions/team-invitation.ts:164`
**Problem**: The shareable invite link generator inspects `reqHeaders.get("host")` but does not check `reqHeaders.get("x-forwarded-host")`.  
**Why it matters**: Deployments behind certain reverse proxies, load balancers, or CDN edge layers can rewrite the `host` header to an internal service name, causing generated links to display an internal address instead of the public domain.  
**Suggested fix**: Check `reqHeaders.get("x-forwarded-host") || reqHeaders.get("host")` when deriving the public link hostname.
