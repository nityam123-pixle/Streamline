## Strengths

* **Anti enumeration and timing defense**: Submitting unregistered emails returns the identical confirmation message as registered accounts, paired with a synthetic jittered delay (>= 400ms) that eliminates timing side channel account enumeration.
* **Token namespace separation**: Restricting reset tokens to the `reset-password:${email}` prefix prevents cross feature token reuse (e.g. attempting to submit an email verification token for password reset).
* **Atomic consumption**: Conditional update via Prisma `updateMany` with `consumedAt: null` and `expiresAt: { gt: now }` eliminates parallel race conditions and replay attacks.
* **Cross device session revocation**: Calling `db.session.deleteMany({ where: { userId: user.id } })` immediately invalidates active sessions across all devices while preserving session isolation for other users.
* **Client side token stripping**: Stripping the raw token from `window.location.search` immediately upon mount prevents shoulder surfing and token leakage via browser history or referrers.
* **Referrer policy protection**: Proxy sets `Referrer-Policy: no-referrer` on all responses to protect tokens in outgoing requests.
* **Live password complexity feedback**: Real time checklist on `/reset-password` guides users through character length, letter, number, and matching confirmation requirements.
* **Exhaustive test suite**: 28 automated tests in `tests/auth/password-reset.test.ts` covering schemas, actions, security invariants, concurrency, and mock logging.
